# 云端整理：实现与验证（v0.4.2）

## 当前范围

按用户最新要求，手动对齐仅做 **网盘回收站删除、同目录文件重命名**。上传、内容覆盖、新建目录由官方备份负责。`reconcile.Writer` 接口及百度适配器已移除 upload、copy、mkdir 入口；旧版完整镜像计划会被拒绝。

| 本地与云端状态 | 处理 |
|---|---|
| 同名文件内容一致 | KEEP |
| 本地文件在云端尚无匹配内容 | WAIT；保留同名旧版及该文件的历史副本 |
| 带 `(n)`、`（n）` 或 ` (n)` 后缀的云端文件与本地内容匹配 | RENAME；已有同名旧版先回收，再重命名正确版本 |
| 历史副本且当前版本确认就位 | REMOVE |
| 本地不存在的其他云端内容 | REMOVE；执行前再次确认本地仍不存在 |
| 本地不存在的最外层云端目录 | 整目录回收并剪枝；不扫描、逐项删除其内部内容 |
| 类型冲突、名称歧义、本地读取变化 | 跳过相关项，其他独立项继续 |
| 文件/子目录读取失败 | UNVERIFIED，保护对应范围及祖先和关联版本；继续比较与整理其他范围 |

后缀只是候选识别，选择正确版本依赖完整 MD5 与大小。本地真实存在的 `a(1).txt` 会优先拥有自己的后缀副本，不会被当成 `a.txt` 的冗余版本。不会根据 `(2)` 比 `(1)` 大就推断它更新。

## 执行与部分重试

1. 先逐项重命名，再逐项删除；云端管理操作串行调度。
2. 每个操作重读相关元信息，检查预览中的文件身份、大小、时间、哈希及当前本地状态。整目录回收仅核对目录元信息、本地根目录可访问及同路径仍不存在，不再完整复核子树。
3. `31171` 与网络错误退避重试，重试前再次检查状态；文件已不存在视为幂等完成，不反复等待。重命名响应丢失时，可通过目标正确且来源消失确认完成。
4. 单项失败不会终止其他独立项。重命名失败时，只阻止它对应历史副本的删除。
5. GUI 保留未完成项。成功操作不会重放，重命名前旧版已回收的状态会传给后续重试。若官方客户端已完成目标更新，可将剩余来源副本转为单独清理项，无需重新扫盘。
6. 页面刷新可从同一 GUI 服务恢复剩余预览；关闭启动窗口/服务后不保留执行计划，须重新扫描。当前不导入旧版 JSON 报告作为可执行计划。
7. 扫描失败按范围隔离。单个云端目录返回 600、文件状态读取失败或子目录不可读时继续后续分支；失败范围不算 WAIT。执行器也逐项阻止涉及未核实范围及其祖先、关联版本的操作。
8. “仅补扫失败范围”保留成功的两端索引及内容哈希，只读失败目录/文件。成功删除和重命名会更新保留索引，补扫不会重新加入已完成项。服务退出后内存索引失效；旧版 JSON 报告没有完整索引与哈希，不能恢复为可执行状态。

所有删除进入网盘回收站；恢复期限以网盘实际显示为准。仍保留清理数量/容量确认、空本地目录保护和根目录访问检查。可定位的扫描缺口只保护相关范围；根目录不可验证、全局截断、无法隔离的扫描异常仍阻止执行。

整目录预览明确包含其全部内容，内部临时文件和 `desktop.ini` 不再阻止父目录回收；目录本身命中排除规则时仍保留。因内部文件数和容量未知，单列未展开目录并要求现有额外确认，不能将未知值当零绕过阈值。元信息无法证明未扫描子树没有变化，官方客户端在预览后写入该目录的内容也可能随之回收，应等备份空闲后执行。

这能减少与官方客户端重复上传造成的工作，但删除/重命名仍可能与其异步任务竞争。没有服务端锁或原子事务，不声称与正在工作的官方备份绝无冲突。

## 扫描与性能

- 云端按目录自上而下分页扫描，最多 4 个目录 worker。本地已不存在的最外层目录记为整目录回收，不再入队扫描；保留分支继续扫描，可定位的失败只隔离对应范围。只读 probe 默认保留完整遍历及原有完整性判定。尚未启用 `PrepareFilesDirectoriesDiff(cursor)`，因为未完成特殊备份目录的增量完整性验证。
- 本地哈希最多 2 个 worker。保留已有 `reconcile-hashes.json` 缓存的兼容读取；取消完整重读可复用大小、纳秒修改时间未变的哈希。快速模式不保证发现保留原大小和时间的内容改写。
- 只计算内容比较和只读探测需要的哈希，不再计算上传分块哈希。
- 管理请求默认起始间隔 200 ms，失败最多 5 次退避尝试；这是可调整的保守起点，不是百度公布的额度。
- 本地 UTF-8 路径超过 250 字节不再被错误拒绝；使用真实文件访问结果判断可读性。
- 进度接口独立于执行锁，每 800 ms 刷新阶段、项数、已读取字节与最近日志。失败/跳过不显示成功的 100%。

云端内容比较依赖 API 返回正确的完整 MD5；没有逐文件下载做字节比较。本轮验证没有操作真实账号的云端内容。

## 验证

离线测试覆盖：正确版本选择、真正的括号文件名、全角/空格后缀、缺失版本等待、排除项保护、类型冲突子树保护、部分失败继续、旧版已回收后的重试、异步忙碌、重命名成功但响应丢失、官方任务先完成目标、当前本地路径重新出现、目录子树变化、空根目录/扫描完整性/确认/阈值、旧版计划拒绝、剩余计划恢复、正常不存在不重试、中文路径和哈希缓存。另验证前端预览、执行、失败项重试与浏览器布局。

目录剪枝回归使用含 100 个分支的假云端：完整遍历需要 202 次目录列表调用，整理预览只需 1 次，执行只删除父目录 1 次且不再列目录。还覆盖空目录、内部排除项、保留本地匹配分支、目录重新出现、目录身份变化、失败后剩余目录重试和未知容量确认。这是请求次数验证，不能等同实际网盘耗时倍数。

扫描容错测试覆盖 600 失败后继续比较与删除、失败范围无假 WAIT、执行层范围保护、文件状态/子目录读取错误、关联后缀版本保护、单独补扫成功/再次失败、已完成动作不重放、成功哈希复用，以及根目录读取失败保留结果但阻止清理。

```powershell
go test -race ./internal/reconcile ./internal/pcscommand ./internal/pcsfunctions/pcsupload ./baidupcs
go test ./internal/reconcile -run '^$' -bench BenchmarkPlanStrategies -benchtime=3x -count=1
```

基准使用内存假云端，只有本地读盘和规划开销，不能代表真实网盘吞吐。当前优化优先减少重复传输和失败后的重复扫描；实际耗时仍受云端目录数量、API 延迟和限流影响。

设计参考：[rclone 的内容匹配与服务端重命名](https://rclone.org/docs/#track-renames)、[Syncthing 的索引和扫描](https://docs.syncthing.net/users/syncing.html)、[restic 的变化检测边界](https://restic.readthedocs.io/en/stable/040_backup.html#file-change-detection)。
