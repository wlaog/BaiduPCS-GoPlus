# BaiduPCS-Go Backup Reconcile（百度网盘自动备份一键对齐）

> 本文保留原始需求。用户最新指示已将功能收敛为删除与重命名，单项失败继续其他独立项；当前规范见 README 与 AGENTS.md。

> 面向 Coding Agent 的项目需求 / 实施说明。**先阅读、验证，再修改代码；不要直接对真实数据执行删除。**

## 1. 背景与目标

用户主要在 Windows 台式机办公，偶尔使用笔记本；已有百度网盘官方 Windows 客户端，正在用其中的**自动备份**功能（云端显示“来自：本地电脑”），另有一块 2TB 移动 SSD 做独立备份。

当前自动备份的实际观察：

- 本地新增文件：自动上传；
- 本地删除文件：云端旧文件仍保留；
- 本地修改文件：云端可能保留旧版本，同时生成 `filename(1).ext` 等副本；
- 结果：长期编辑的工作区在云端堆积了大量不再对应本地现状的文件。

**目标：保留官方客户端原有的自动备份功能，不替换、不常驻接管它。新增一个用户手动触发的“对齐本地 / Reconcile now”动作，使指定云端备份目录在执行完成后，与指定本地目录具有一致的相对路径、文件名和文件内容，清理已经不在本地的冗余文件。**

这是**单向、按需的镜像整理**，不是后台实时双向同步。**本地目录是此功能的唯一权威源（source of truth）**；云端改变不得反向影响本地。

## 2. 上游仓库

- GitHub: https://github.com/qjfoidnh/BaiduPCS-Go
- 基于此仓库创建独立分支，尽量复用已有的认证、列目录、获取元信息、上传覆盖、移动、删除等代码。
- 开发前检视当前版本源码、CLI flags/API 与许可证。仓库文档说明上传支持 `--policy overwrite`，以及 `rsync`（仅按大小判定跳过，**不能**当作可靠的内容一致性检测）。请以实际代码行为为准。
- 不要假设自动备份的“来自：本地电脑”一定等同于可正常操作的网盘普通路径，也不要假设可以用公开 API 管理它。**先做下面的可行性验证。**

## 3. 必须先完成的可行性验证（Go/No-Go）

使用独立的小型**测试备份任务**和测试文件；不得在真实工作目录上试验：

1. 官方客户端创建测试自动备份，记录本地绝对路径以及云端看到的目录路径。
2. 用 BaiduPCS-Go 的现有 `ls`/`meta` 等功能尝试定位、递归读取该目录；确认是不是普通可枚举的云端文件对象，以及 API 返回的稳定标识、路径、大小、时间、可用哈希。
3. 在测试目录验证上传覆盖、移动/重命名、删除及回收站行为；确认权限与路径映射正确。
4. 官方备份任务仍开启时，人工在云端处理一个测试冗余副本，观察官方客户端是否立刻重新上传、冲突命名或恢复旧文件；必要时尝试**暂停自动备份任务后整理，完成后恢复**，记录能否通过受支持的方式暂停及恢复。
5. 验证云端分页列举是否完整、中文/空格/括号路径如何转义，以及同名文件内容更新的比较能力。

**Go 条件**：可以稳定访问目标备份目录、逐个操作测试文件，而且有可验证的办法防止官方备份客户端与整理任务相互竞争。

**No-Go**：若特殊备份目录无法被第三方 API 访问，或清理结果会被官方客户端持续复原，**停止对该目录开发破坏性动作**。给用户报告限制，可提出备选：迁移至普通网盘目录作镜像，或改用真正支持版本历史的同步产品；不能偷偷把工程范围扩大，也不能声称已成功兼容。

## 4. 产品交互与预期行为

MVP 优先实现 CLI 子命令；如果容易，可增加小型 Windows GUI 开关/按钮，但 GUI 不是前提。推荐命令风格（具体名称可按上游架构调整）：

```powershell
# 默认只预览，不改变云端
BaiduPCS-Go reconcile --local "D:/WorkSync" --remote "/测试备份/WorkSync" --dry-run

# 明确确认后才执行
BaiduPCS-Go reconcile --local "D:/WorkSync" --remote "/测试备份/WorkSync" --apply
```

GUI（可选）：一个醒目的 **“对齐本地（手动执行）”** 操作按钮；平时显示 **“自动备份：由百度网盘官方客户端管理”**。按钮不是“永久开启镜像”；执行一次即停止。必须可以查看差异摘要、取消操作、查看详细日志。

预览最少列出四类：`UPLOAD`（云端缺失）、`REPLACE`（路径相同但内容不同）、`REMOVE`（云端多余，包括 `(1)` 副本）、`KEEP`（一致）。可再列 `CONFLICT`（类型不符、不可判断、正在编辑等）。

**示例：**

本地：

```text
D:/WorkSync/
  paper.docx            # 当前版本
  figures/plot.png
  notes.md
```

云端（自动备份历史残留）：

```text
/备份/WorkSync/
  paper.docx            # 旧版
  paper(1).docx         # 自动生成的重复版
  figures/plot.png
  deleted_old.txt
```

预期预览：替换 `paper.docx`、上传 `notes.md`、保留内容一致的 `figures/plot.png`、把 `paper(1).docx` 和 `deleted_old.txt` 标成云端多余文件。**如果本地确实存在 `paper(1).docx`，必须保留该文件，不能根据名称模式无脑删除。**

执行后，云端镜像目录在同一时间点应等于本地文件树；但必须定义清楚异常、未完成上传及并发编辑的处理方式。

## 5. 核心算法（重点复用上游能力）

1. 配置并校验**明确的本地根目录和云端根目录**，禁止空路径、根目录 `/`、路径越界、路径别名误指向其他区域。
2. 完整扫描两端文件树，使用相对于根目录的**规范化相对路径**建立映射；区分文件与目录。扫描失败或分页不完整则中止，**绝不删除**。
3. `UPLOAD`：本地存在、云端不存在；`REPLACE`：同路径文件且内容不同；`REMOVE`：云端存在、本地不存在；`KEEP`：经可靠规则确认一致。
4. 文件内容一致性：优先采用可靠的双方可比哈希；若云端缺少可靠哈希，不可以只靠“同名 + 同大小”推断完全相同。可以保守地重新上传覆盖有疑义的文件，或标为待确认；避免为检查每个文件强制下载几百 GB。
5. 顺序原则：先完成新增/覆盖上传并验证成功，再处理多余文件；任何上传失败、云端目录列举不完整、权限异常、路径映射歧义，都必须阻止后续清理步骤。
6. 整理开始前要求官方自动备份任务处于**已暂停或可验证的无竞争状态**。如果无法确认，默认拒绝执行 `--apply` 中的删除操作。
7. 执行前后记录文件清单和操作结果；出现中断允许安全重试（幂等）；输出摘要：新增 N、替换 N、拟移除 N、失败 N、字节数。
8. 本地正在修改的文件：至少在读取前后校验大小、修改时间（有条件可校验哈希），变化则跳过并警告，不把半写入文件误当作定稿。
9. 不默认跟随 Windows junction、符号链接或其他指向根目录外的链接；避免递归环和跨目录误同步。
10. 支持排除规则，如 `.git/`、临时文件、缓存目录；默认不排除用户真实文件，排除规则需明确记录，**排除的云端对应项目不得自动删除，除非另行明确授权**。

## 6. 删除防护（必须落实）

- **默认 dry-run**。`--apply` 需要交互式确认，且展示预计删除数量和容量。
- 删除前优先**移动云端多余文件到镜像根目录之外的隔离区**（例如 `/BackupReconcile_Quarantine/<timestamp>/...`），保留原相对路径及清单；不要默认永久删除或清空回收站。注意隔离区不能再被同一镜像规则扫描到。
- 若网盘无法可靠移动到隔离区，则要求额外确认，MVP 可直接阻止清理并报告，不要自动降级为永久删除。
- 检查本地根目录是否存在、可读、扫描完成，并设置防误删阈值：例如云端将移除 >10% 的文件数或 >10GB 时，需二次确认；阈值可配置。检测本地目录疑似被误清空时强制停止。
- 不触碰用户指定云端根目录以外的任何文件，不修改本地文件，不改变官方客户端备份任务的设置。
- 覆盖行为也可能导致旧云端内容丢失：优先保留可恢复的版本或在隔离区保存旧版；如果无法安全保存旧版，明确告知并征得确认。
- 所有测试默认使用临时测试账号/测试目录与伪造数据；禁止在 CI 使用真实账号凭据，禁止日志输出 Cookie、BDUSS、STOKEN 等机密信息。

## 7. 推荐工程分层

```text
cmd/...                           # CLI 注册 / 参数解析
internal/reconcile/               # 新增：尽量独立于上游现有逻辑
  scan.go                         # 本地与远端扫描
  diff.go                         # 生成差异计划
  apply.go                        # 事务式执行及失败处理
  safety.go                       # 路径保护、阈值、并发检测
  report.go                       # 预览报告与日志
  *_test.go                       # 使用 mock RemoteFS 的单元测试
```

上述目录仅为建议。Agent 应先检查真实项目组织、现有远端 API、配置与命令框架，避免重复封装或改动现有上传/删除行为。可定义 `RemoteFS` 接口，方便用 fake 测试创建、重命名、上传、移动和失败回滚场景。

## 8. 验收标准

- [ ] 不开整理功能时，上游 BaiduPCS-Go 原有命令不受影响；百度网盘官方客户端的自动备份照常运行。
- [ ] 从指定自动备份目录成功列出所有测试文件，路径映射经验证正确；若不可访问，清楚报告不支持而不删除。
- [ ] 云端只有旧版 `a.txt`，本地有新版 `a.txt`：对齐后云端为最新版，不额外生成 `(1)`。
- [ ] 本地有 `a(1).txt` 时，不能错误删除它。
- [ ] 本地已删除文件：预览标出，确认后移动到隔离区，当前镜像中不再出现。
- [ ] 中断、鉴权失败、部分上传失败、扫描失败：**不会执行冗余清理**。
- [ ] 全程禁止触碰映射根路径之外的用户文件；本地文件绝不被删除。
- [ ] 跑完之后再次 dry-run，结果为零差异或有清楚说明的未处理项。
- [ ] 官方备份重新启用后，观察一段时间不出现大量重复或恢复旧版的情况；如不能保证，不宣称兼容。
- [ ] Windows 路径、中文目录、空格、括号、较大文件、空目录、分页以及大小相同内容不同的文件有测试覆盖。

## 10. 范围外（不要擅自扩展）

- 不做持续后台监控或双向同步。
- 不替换或逆向修改百度网盘官方客户端。
- 不重构整个 BaiduPCS-Go 项目。
- 不做自动永久删除、自动清空回收站。
- 不处理真实用户科研目录，直至用户审阅预览结果并明确授权。

**最终一句话**：用户希望继续使用百度网盘自带的自动备份，以便随时上传新增和修改内容；只在用户主动点击“对齐本地”时，用一次安全的单向镜像操作将云端备份整理成与本地当前目录一致的文件树，并能恢复被清理/覆盖的历史内容。
